# E1-06 evidence

`E1-06.AC1` (no frame drops below 50 fps on a mid-range laptop, with a Chrome performance trace attached to the
PR) needs a run on real hardware. Until it's recorded here as a level-2 heading with the criterion's tag, the
AC gate reports it as untraced, on purpose.

## Measurements so far, for the reviewer

Measured with a `requestAnimationFrame` counter on the main thread (which lags the compositor), in headless
Chromium on the build machine at 1366 × 768, against the production build:

| Run | Average | Longest frame |
|---|---|---|
| Idle page (baseline) | 60 fps | — |
| The Crossing, first version (SVG rings, no layer hints) | 31 fps | 83 ms |
| The Crossing, as merged (`will-change` layers, HTML rings) | 37 fps | 50 ms |
| The Crossing, as merged, headless with the GPU enabled | 39–43 fps | start-up hitches |

Headless Chromium rasterises in software here, so these numbers understate a laptop with a GPU. They're not
a substitute for the trace AC1 asks for.

**To record AC1:**
1. Open `/#/settings` in Chrome on a mid-range laptop.
2. Start a Performance recording, and press **Replay the Crossing**.
3. Stop the recording after the map appears. Check the Frames track for frames under 50 fps (longer than
   20 ms), and attach the trace to the PR.

How the sequence keeps its cost down:
- Every moving layer (the room, the light, the rings, the map, the light shafts) is its own compositor layer
  (`will-change: transform, opacity`).
- Only `transform` and `opacity` animate.
- The rings are HTML elements, not SVG children, so moving them never repaints the SVG.
