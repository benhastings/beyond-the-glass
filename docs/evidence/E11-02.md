# E11-02 evidence

`E11-02.AC2` (no long task over 100 ms during normal war-room interaction, with a performance trace attached)
needs a trace from real hardware. Until it's recorded here as a level-2 heading with the criterion's tag, the AC
gate reports it as untraced, on purpose.

## Measurements so far, for the reviewer

Long tasks (PerformanceObserver `longtask`) in headless Chromium at 1920 × 1080, production build, while running
three commands in the war-room terminal, bringing up Dashboards (Alt+5), Explore (Alt+6) and Argo CD (Alt+3), then
leaving the background clock running for six seconds:

| Build | Long tasks |
|---|---|
| Before (E10-04) | one of 105–107 ms, when the Dashboards pane first rendered |
| After (this PR), three runs | 66 and 55 ms; 61 and 51 ms; 58 and 65 ms |

What changed: each dashboard panel runs its own query as it renders, rather than all of them in one
synchronous step, and the war room brings panes up in a React transition, so the work is split into pieces that
yield to input.

**To record AC2:** open `/#/stormwatch` in Chrome, start a Performance recording, run a few commands, switch
panes (Alt+1–7) and wait 20 seconds, then stop. Check the Main track for tasks marked long over 100 ms, and attach
the trace to the PR.
