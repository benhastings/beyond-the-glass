<Step id="reference" title="Reading an image reference">

An image is named like this:

<CodeBlock
  language="text"
  caption="An image reference"
  code="registry.example/ravenpost/api:1.14.0"
/>

- `registry.example` is the **registry**: the server images are pulled from.
- `ravenpost/api` is the **repository**: one service's images, every version.
- `1.14.0` is the **tag**: a label for one version.

<Step id="layers" title="Layers, and why images don't change">

<Depth>
  <ELI5>
    An image is built in layers, like a stack of sheets. Each step of the build adds a sheet. Once
    the stack is made, nobody changes it. To change something, you build a new stack.
  </ELI5>
  <Operator>
    Each build step adds a read-only layer. Layers are shared between images, so pulling a new
    version downloads only the layers that changed. Because layers never change, an image built once
    runs the same everywhere, and rolling back means running the previous image.
  </Operator>
</Depth>

</Step>

<Step id="tags-digests" title="Tags and digests">

A **tag** is a name someone chose, and it can be moved to a different image. A **digest** is a fingerprint of
the image's contents, such as `sha256:77f3…`. If the contents change, so does the digest.

So a tag tells you what someone meant to run, and the digest tells you what is running. `latest` is a tag
like any other: it means "whatever was pushed last", which can change under you between two pod starts.

<Callout kind="warn">
  A pod that asks for a tag the registry doesn't have can't start: its STATUS shows `ErrImagePull`,
  then `ImagePullBackOff`, and the events say "not found". A missing `v`, a typo or the wrong
  registry are all it takes. You'll fix one in the Chartroom.
</Callout>

</Step>
