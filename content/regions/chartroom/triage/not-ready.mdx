<Step id="quiet" title="The quiet failure">

<Rosetta id="lb-health-check-probes" />

Nothing is crashing, nothing is Pending, and every pod says Running. But READY reads `0/1`, and every
request to the service fails. A Service sends traffic only to **Ready** pods, so with none Ready its
endpoints list is empty: `<none>`.

The probe is the usual suspect: a readiness check on a path or port the program doesn't serve fails every
time, and the events say so: `Readiness probe failed: HTTP probe failed with statuscode: 404`.

<Step id="fix" title="The fix">

The api's probe was changed to `/readyz`; the api serves `/ready`. And because the api uses the Recreate
strategy, there were no old pods left to keep answering. `fixes/api.yaml` puts the path back: apply it,
and the endpoints return as the pods turn Ready.

<Callout kind="info">
  Here you fix it with kubectl, so you can see the cluster respond. In our world, Ravenpost is
  deployed from Git, and a kubectl fix is put back at the next sync: the real fix goes through Git,
  as you will do in Mirror Lake.
</Callout>

</Step>
