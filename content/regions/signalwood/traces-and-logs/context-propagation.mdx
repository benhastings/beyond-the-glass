<Step id="propagation" title="How the trace ID travels">

When a service calls another, its OpenTelemetry SDK adds the trace's context to the request, in the
`traceparent` header: the trace ID, and the calling span's ID. The next service's SDK reads it and makes its
span a child. Every service on the path has to do this. If one doesn't, the trace stops there, and what it
calls starts a new trace with no parent.

<Depth>
  <ELI5>
    Each depot writes the parcel's tracking number on the label for the next depot. If one depot
    forgets, the next depot starts a new tracking number, and the parcel's history splits in two.
  </ELI5>
  <Operator>
    Symptoms of broken propagation: traces that end at one service, and orphan traces rooted at its
    callees, at the same moments. The usual causes: an HTTP client that isn't instrumented, a new
    SDK version, a proxy that strips headers, or two services using different propagation formats.
  </Operator>
</Depth>

</Step>
