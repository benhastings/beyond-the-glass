<Step id="reflection" title="Git is the shore; the cluster is its reflection">

<Rosetta id="manual-change-gitops" />

In GitOps, a Git repository holds the desired state: every Deployment,
Service and ConfigMap, as files. **Argo CD** watches that repository and the cluster, compares the two, and
makes the cluster match Git. Like still water, the cluster should reflect the shore exactly; a ripple on the
surface is **drift**.

<Depth>
  <ELI5>
    Git holds the plan. Argo CD looks at the plan and at the cluster, again and again. If they
    differ, it can make the cluster match the plan.
  </ELI5>
  <Operator>
    An Argo CD **application** points at a path in a repo and a namespace in a cluster. Every few
    minutes (three, by default) it renders the manifests and compares them with the live objects.
    With automated sync it applies the difference; with self-heal it also undoes changes made
    directly in the cluster.
  </Operator>
</Depth>

</Step>

<Step id="two-statuses" title="Sync and health are different questions">

- **Sync status** asks: does the cluster match Git? `Synced` or `OutOfSync`.
- **Health status** asks: is what's running working? `Healthy`, `Progressing`, `Degraded`, `Missing`.

They're independent. An app can be **Synced and Degraded** (Git asked for something broken, and the cluster
faithfully runs it), or **OutOfSync and Healthy** (Git has a change nobody has applied yet).
